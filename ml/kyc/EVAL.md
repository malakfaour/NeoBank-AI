# KYC Threshold Evaluation (DEVATTECH-100 / DS-3)

## Decision matrix

The production defaults remain unchanged and can be overridden through environment settings.

| Match score | Outcome |
|---|---|
| `score >= 0.80` | Approve |
| `0.60 <= score < 0.80` | Flag for manual review |
| `score < 0.60` | Reject |

Settings: `KYC_MATCH_APPROVE_THRESHOLD=0.80` and `KYC_MATCH_FLAG_THRESHOLD=0.60`.

## Genuine-pair findings

The evaluation used the 500 same-person LFW test pairs generated by `fetch_lfw_pairs.py`. The source images are low-resolution 94×125 face crops, so the evaluator upscales them for detector compatibility without changing their content. ArcFace successfully scored 473 pairs; 27 failed face detection or DeepFace preprocessing and were excluded from score statistics.

- Successful pairs: **473 / 500 (94.6%)**
- Mean match score: **0.3146**
- Minimum match score: **0.0000**
- Maximum match score: **0.9936**

| Approve / flag thresholds | Approved | Flagged | Rejected |
|---|---:|---:|---:|
| 0.75 / 0.55 | 34 (7.19%) | 58 (12.26%) | 381 (80.55%) |
| **0.80 / 0.60 (current)** | **29 (6.13%)** | **41 (8.67%)** | **403 (85.20%)** |
| 0.85 / 0.65 | 27 (5.71%) | 25 (5.29%) | 421 (89.01%) |

## Recommendation

Do **not** change the production thresholds from 0.80/0.60 based on this evaluation. The unusually low genuine acceptance rate shows that cropped, low-resolution LFW images are not representative of the higher-resolution selfie and ID-photo capture flow; lowering the thresholds by 0.05 still rejects 80.55% of genuine pairs and would reduce security without producing an acceptable genuine-user outcome. A threshold change requires a representative, consented production-like validation set containing both genuine and impostor pairs. Therefore no config default was changed beyond moving the existing values into settings.

## Spoof/liveness evaluation

**Incomplete: no DS-3 spoof images were present in `ml/kyc/eval_data/spoof_pairs/` at evaluation time.** The evaluator is wired to the same `check_liveness()` function used by the KYC task and reports the anti-spoof score distribution plus the number passing as real at the 0.70 liveness threshold. With zero supplied images, no spoof pass/fail rate or score distribution can be claimed. Teammate print-photo and screen-replay samples must be placed in the gitignored directory and the evaluator rerun before DS-3 spoof acceptance can be signed off. No face images are committed to Git.

## Reproduce

From the repository root, after populating the gitignored evaluation directories:

```powershell
$env:PYTHONUTF8='1'
.\backend\venv\Scripts\python.exe ml\kyc\evaluate.py
```
